## The publish loop (Windows PowerShell)

```powershell
cd "B:\Dropbox (Personal)\Personal Files\personal_web_2026\ruidai-site"
python build.py                          # regenerates docs/  (needs: pip install pyyaml markdown)
git add -A; git commit -m "what changed"; git push
```

Live about a minute after the push. Images on the live site are cached ~10 min; Ctrl+F5 if stale.

## Design decisions (so we don't relitigate them)

- **Self-contained pages.** Fonts, images, and the D3 subset are embedded in the HTML — no CDN,
  no Google Fonts requests. Done so the site renders in mainland China (jsDelivr and Google are
  blocked/unreliable there) and when opened as a local file. Pages are ~480–500 KB each; fine.
- **GitHub Pages, not a VPS.** Free, no maintenance. From mainland China `github.io` is reachable but
  slow/intermittent. If a Shenzhen colleague finds it too slow, options are a Gitee Pages mirror or a
  Hong Kong static host under the same domain; a US VPS (Linode etc.) would not help.
- **Research page defaults to the FT50 tab.** All / UTD24 / Other are one click away.
- **Coauthor graph** sits on a warm parchment panel (`#e9e6de`) like all other tiles; nodes have soft
  blurred edges; the graph ignores the journal-list tab (so it's fully lit on load) and only dims when a
  topic / author / search filter is active. Hub node is ink-coloured.
- **All dark panels unified** to the parchment tone (project tiles, sketch placeholders, footer).
- **Impact stats** (Scholar citations, h-index, SSRN downloads, "as of" month) sit at the top of the
  Research page, above the Publications heading. They were tried on the home page and removed — the
  home page is name, roles, bio, three links only. No email link in the top nav or link row; the CONTACT
  icon at the bottom of the home page still opens mail.
- **Phone layout** of the home page: portrait as a dim full-screen backdrop behind the text (the
  original design). A "portrait header on top, text below" variant was tried and rejected.
- **Cache-busting query strings were removed** — they broke images when the page is opened as a local
  file on Windows. Tile images are embedded instead.
- **Tab icon** is the character 睿 in gold on the site's dark rounded square, set in *Zhi Mang Xing*
  (行草 running-cursive, OFL, from Google Fonts). Chosen over Ma Shan Zheng (楷), Long Cang (行), and
  Liu Jian Mao Cao (草). The glyph outline was extracted with fontTools into `assets/favicon.svg`;
  PNG/ICO sizes were rendered from it. A root `/favicon.ico` is also served (build.py copies it) because
  browsers request that path by default and Chrome caches "no icon" aggressively — if a new icon
  doesn't appear, open the site in a fresh tab or Ctrl+F5.
- **Conferences page is "visible but not pronounced"** — the pattern from Dexin Zhou's site
  (dzfinance.notion.site), where the Conference DB hangs off the home page but is absent from the
  persistent nav. Here: one `Conferences` entry in the home-page `links:` list, nothing on the Research
  page, no new top-nav item, and `<meta name="robots" content="noindex">` so it doesn't compete with
  his name in search. Noindex is not privacy — the URL is public to anyone who has it.
- **Slide decks are linked files, not embedded.** Everything else on this site is base64-inlined; decks
  are not (the FMA AI-washing deck alone is 4.8 MB). They live in `assets/slides/`, are copied to
  `docs/slides/`, and the download button shows the format and file size so he knows what he's pulling
  over conference wifi. Filenames are descriptive (`dai-fma2026-ai-washing-ipos.pptx`) because that name
  is what lands in a phone's Downloads folder.
- **The conferences page skips the banner image** and uses a flat dark header instead — it is opened
  one-handed in a session room, so it loads at 180 KB against the other pages' ~500 KB.
- **Working papers under R&R** are noted with a badge (e.g. "R&R, Journal of Banking & Finance") rather
  than a separate status; `status` stays `Working paper`.

## Known quirks / gotchas

- Git in the Dropbox folder, when driven from Claude's device bridge, can't delete its own lock files;
  they get moved to `personal_web_2026\_to_delete\git-tmp\`. That folder is safe to delete any time.
  Committing from your own PowerShell has no such issue.
- `update_stats.py`: SSRN fetch works; Google Scholar often blocks scripts — it then keeps the old number
  and says so; edit `stats.yml` by hand in that case (or ask Claude to read the live number via Chrome).
- The GitHub fine-grained token used for the initial push should be deleted (GitHub → Settings →
  Developer settings → Fine-grained tokens → `cowork-launch`) if it hasn't been already.

## FMA 2026 (Tampa, Oct 14-17 2026)

Three appearances are on the page, newest first, as PDFs: AI-washing presentation (38 pp), Lin
discussion (11 pp), Avino discussion (8 pp). Sources stay in Dropbox-Penn `Rui Dai/paper-discussion/`.

**pptx -> pdf on this Mac** (`pptx2pdf.sh`): there is no LibreOffice and no Keynote, and PowerPoint's
sandbox rejects AppleScript access to ordinary paths with error -9074 — Dropbox, `~/Documents`, even
`~/Library/Containers/com.microsoft.Powerpoint/`, and a Launch Services `open` leaves zero
presentations. What works: copy the deck into the **Office group container**
(`~/Library/Group Containers/UBF8T346G9.Office/`) and convert it there, saving with
`save p in (POSIX file outPath) as save as PDF` — a plain string path gives a -50 parameter error.

**The page URL is `/slides.html`.** It was briefly `/conferences.html`; build.py writes a redirect
stub at the old path, which can be dropped once no shared link points there. The title, heading and
home-page link all still say Conferences — only the filename changed.

Also: this Mac had neither `pyyaml` nor `markdown` until now (the site had only ever been built on
Windows); `python3 -m pip install --user pyyaml markdown` fixed it. Pushing from this Mac now works over **SSH**: an ed25519 key was generated here
(`~/.ssh/id_ed25519`, registered on GitHub as "Mac mini Tampa") and the remote was switched to
`git@github.com:ruidaiphd/ruidai-site.git`. HTTPS pushes failed — no credential in the keychain, and
the username/password prompt is a dead end since GitHub dropped password auth.
